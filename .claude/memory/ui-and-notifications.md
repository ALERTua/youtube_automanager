## NiceGUI

- `ui.run(language=...)` changes only the built-in texts of Quasar components. For the strings of the application, use `gettext` catalogs that Babel extracts.
- NiceGUI 3.17 keeps one global application. `ui.run_with(app)` mounts it at the root of `app`, and the routes that `app` already has stay first. NiceGUI starts before the lifespan of `app` and stops after it.
- With NiceGUI at the root, an unknown path, also under `/api/`, gets the HTML 404 page of NiceGUI, not the JSON 404 of FastAPI. So the API router ends with a route for `/api/{path}` that answers the JSON 404.
- In a page function, `request.app` is the NiceGUI application, not the FastAPI application of `create_app`. A page gets the services from the shell, as the argument of its builder.
- After the global application served a request, a second `ui.run_with` in the same process fails with "Cannot add middleware after an application has started". Each test that calls `mount_ui` uses the fixture `nicegui_globals`.
- At its end, `nicegui.testing.general.nicegui_reset_globals` removes the module of each page function and its parent packages from `sys.modules`. After that, a `monkeypatch.setattr` with a dotted path such as `"youtube_automanager.web.app.setup_logging"` fails with `AttributeError`. The fixture `nicegui_globals` empties `Client.page_routes` first, so the modules stay.
- The `user` fixture of NiceGUI runs only the lifespan of NiceGUI and sends each request directly to NiceGUI, so the lifespan of the service does not run and a page gets no services. A page test runs the lifespan of the whole application and gives `nicegui.testing.User` an `httpx.AsyncClient` with `httpx.ASGITransport(app)`. The async tests use the pytest plugin of anyio, not pytest-asyncio.
- In the user simulation, a click goes only to the listeners of the found element, not to its parents. Find a clickable element by its marker.
- `run.io_bound` returns `None` instead of a `CancelledError` when the call is cancelled or the application stops. A `ui.timer` whose callback awaits `run.io_bound` then survives the cancel at the stop of the service: the stop waits 2 s and logs "Could not cancel N tasks within timeout". A page reads the database with `asyncio.to_thread`.
- A `ui.timer` calls its callback at once by default. Give `immediate=False` when the page already read its data.
- One shell route answers each page: `mount_ui` registers `ui.page("/")` and `ui.page("/{path:path}")` with one shell function, and the shell puts `ui.sub_pages` with the route of each registered page into the content column. Each item of the drawer calls `ui.navigate.to`, which changes only the content, because the layout holds a `SubPages` element. The browser keeps the client, the head and `window`, measured in Firefox: `performance.getEntriesByType('navigation').length` stays 1. `on_path_changed` of `client.sub_pages_router` marks the drawer item and sets the title. A full load of a path still gets the shell with the content of that path.
- `ui.sub_pages` runs an async builder as a background task, and the page route does not wait for it, so the first HTML would come without the content, and `User.open` would return before the page read its data. The shell waits for the end of the first build with an `asyncio.Event` that a `functools.wraps` wrapper of each builder sets. `wraps` keeps the signature, so `ui.sub_pages` still gives `services` and the path parameters by name.
- NiceGUI adds the route `/favicon.ico` when it starts, after the routes of `mount_ui`. A catch-all page route added before the start answers `/favicon.ico` with the shell, so `mount_ui` adds `/{path:path}` in `app.on_startup`, which runs after that. The FastAPI routes of `create_app` (`/health`, `/api/...`, `/docs`, `/openapi.json`) and the `/_nicegui/...` routes come first anyway. `tests/test_web_shell.py` checks each of them.
- An unknown path matches the route `/` or the path of a page with a remaining path, so `ui.sub_pages` starts the builder of that page, and later shows its label "404: sub page ... not found". The 404 clears the content but does not cancel the task of the builder (`_set_match` in `nicegui/elements/sub_pages.py`), so the page would grow under the label, with live subscriptions. The wrapper of each builder in `web/ui/__init__.py` therefore builds only for a path that a page owns. The shell answers an unknown path with HTTP 404, and NiceGUI logs a WARNING "... not found".
- `ui.sub_pages` converts a path parameter, and a query parameter with the name of a builder parameter, by the annotation of the builder before the builder starts (`PageArguments.build_kwargs`). A failed conversion, such as "abc" for `int`, raises before the wrapper runs, and the first answer waits the whole `response_timeout` of 3 s and ends with HTTP 500. So `register_page` refuses each builder parameter other than `services` with another annotation than `str`, and the builder converts the text itself with `whole_number` of `web/ui/common.py`. That helper takes at most 18 digits: `int()` of more than 4300 digits raises ValueError, and SQLite refuses an int above 64 bits.
- `ui.sub_pages` builds the page again when the path changes, or when a query parameter changes that the builder has as a parameter (`_required_query_params_changed` in `nicegui/elements/sub_pages.py`, each query change for a `PageArguments` parameter). A page that keeps its view in the query, such as the filters of Rules and History, therefore reads the query with `address_query` of `web/ui/layout.py`, and its builder does not have these parameters. A filter change writes the address with `replace_address`, which sets `router.current_path` and runs `history.replaceState` with the state `{page: address}`: on Back, `sub_pages.js` opens `event.state.page`, so a replace that keeps an old state would open the old address. `ui.navigate.history.replace` writes the state `{}` and does not tell the router.
- An address with the same path and another query keeps the content: a click in the drawer on the shown page, a `ui.navigate.to` of the page itself, Back to an entry with another query. The page follows such an address with an `AddressFollower` of `web/ui/layout.py`, which gets the query. The router calls `on_path_changed` handlers before it changes the content, and NiceGUI has no way to remove one, so the router of a client has one handler that calls the followers that exist. In the user simulation, `user.navigate.to` and `user.navigate.back()` call the router, and a `replaceState` changes no `user.back_history`.
- The rule editor is the sub page `/rules/new` or `/rules/<id>`, and its address keeps the query of the rules page that opened it, so Save, Delete and Cancel go back with the filters. The editor puts the id of its rule into `client.storage` (`RETURN_FOCUS`), and the rules page that builds next moves the focus to the Edit button of that rule. A row button selector of a page with a navigation holds the scope of its table (`rules`, `runs`), so a focus move that ends after the user left the page finds no button of another page.
- At a new address with the same path and no fragment, `ui.sub_pages` scrolls the window to the top with a smooth scroll in the next animation frame (`_handle_scrolling` in `nicegui/elements/sub_pages.py`). A page that opens a part far down on such an address loses it from view, and a `focus()` that comes before that frame does not help, measured in Firefox. With a fragment, NiceGUI scrolls to the element with that id instead, and with no such element it does not scroll. So the address of an open History run ends with `#run-actions`, and the focus of the card brings it into view. A new page (another path) scrolls to the top at once in the next frame, so a focus at its build waits `FOCUS_DELAY_MS`.
- A page that corrects its address when it builds, for example the fragment of a link to a run, writes it with `replace_address(..., only_from=<address of the build>)`. The script runs after the connection of the tab, and a quick Back can come first. Without the condition, the late replace gave the entry of Back the address of the run, measured in Firefox.
- A click in the drawer first asks each `LeaveCheck` of the content (`web/ui/layout.py`). The rule editor asks «Discard the changes?» there and in its Cancel, and `warn_on_unload` sets the flag of the `beforeunload` script in the head, so a reload or a close of the tab with changes gets the warning of the browser. The check ends the flag when the content goes. The Back button cannot ask: `ui.sub_pages` gets the address after the `popstate`.
- `Event.subscribe` in a UI context ends the subscription only at the delete of the client. A click in the drawer deletes the content and keeps the client, so a part of a page subscribes through `Subscriptions` or `RunFollower` of `web/ui/live_runs.py`, which unsubscribe when their element is deleted. A direct `subscribe` in a page adds one more handler at each visit of the page.
- `Event.subscribe` in a UI context also adds `client.on_delete(...)` to the client, and nothing removes that handler when the element goes (`nicegui/event.py` 103-104). A subscription that an element ends itself in `_handle_delete` passes `unsubscribe_on_delete=False`: else each click in the drawer adds delete handlers to the client and keeps the old page in memory. `Client.delete` removes each element and calls its `_handle_delete`, so the subscription still ends with the tab. `test_a_navigation_adds_no_delete_handler_to_the_client` measures it.
- The first HTML of a page gets `color-scheme` "normal" from `dark=None` of `ui.run_with`, and `<div id="app">` is empty, so the browser paints the page light until Vue mounts and `ui.dark_mode` sets the dark body class, about 100 to 200 ms in a measurement. `theme.first_paint_style` therefore puts a style for `body:not([class])` into the head: Quasar gives the body its classes at the mount, so the style acts only before it.
- NiceGUI writes `app.storage` into the folder `.nicegui` of the current folder, or into `NICEGUI_STORAGE_PATH`, and it writes a file only when a page stores a value. The image runs in `/app`, which the service user cannot write to, so a page that stores a value needs `NICEGUI_STORAGE_PATH` under `/data`. `app.storage.user` and `app.storage.browser` also need a `storage_secret`.

- `refresh` of a `ui.refreshable` gives each argument that it gets to the refreshable function as a new argument. An `on_change` handler gets the event, so pass `lambda: view.refresh()` and not `view.refresh`.
- The service cleans the old history when it starts, and it deletes a run that is older than the retention period. A test that seeds a run with a fixed date and then starts the service would depend on the clock. So the autouse fixture `history_cleanup_off` in `tests/conftest.py` replaces `clean_history` in `youtube_automanager.web.app`, and a test of the cleanup puts the real function back with `monkeypatch.setattr`.
- The service plans a daily yt-dlp update, so a test that runs the service at that time would read PyPI and run uv. The autouse fixture `ytdlp_install` in `tests/conftest.py` replaces `update_ytdlp` in `youtube_automanager.web.app` with a `FakeYtdlpInstall`, and a test gives that fake its plan: a new version, an error, or no change.
- The cookie rotation is on by default, so a service with stored cookies would send requests to `accounts.youtube.com`. The autouse fixture `rotation_offline` in `tests/conftest.py` replaces `CookieRotation` in `youtube_automanager.web.app` with a factory that builds the real rotation on a transport that refuses each request and records its URL.
- On Windows, the asyncio event loop connects a socket pair when it starts. A test that patches `socket.socket.connect` before a `TestClient` starts breaks the loop. To refuse the network, patch `socket.getaddrinfo` and `socket.create_connection` after the start.
- In the user simulation, `user.notify.messages` keeps each message of the page, and `should_see` of a text passes when any earlier message holds it. A test that waits for a second message with the same text counts the messages.
- Each setting of the settings page changes only a draft (`web/ui/settings_draft.py`). One floating Save writes only the changed parts, and a form error or a cancel of the question of the processing mode writes nothing. The actions, such as the cookie upload, "Update now" and the add, the change and the delete of a notification target, act at once.
- In the user simulation, a `ui.input` with the prop `type=time` takes and gives a plain text such as `05:30`, so `set_value` works on it as on a text field.
- The fixtures of the page tests (`user`, `settings`, `sessions`, `logging_setups`, `no_logged_errors`) are in `tests/conftest.py`, and their helpers (`running_service`, `store`, `text_of`, `set_value`, `eventually`) are in `tests/ui_support.py`. A page test module has `pytestmark = [pytest.mark.anyio, pytest.mark.usefixtures("logging_setups", "no_logged_errors")]`.
- `User.should_see` of NiceGUI tries 3 times, 0.1 s apart. In a parallel run, a page needed longer, so `running_service` gives it the limit `WAIT_SECONDS` (10 s). The tries end at the first success.
- The fixture `migrated_database` migrates one SQLite file for the test session, and `new_database` copies it for a test. It copies only when the file does not exist yet: when `user` comes before `sessions`, the service of the test already made and filled the database, and a copy would replace its rows.
- In the user simulation, a `ui.refreshable` rebuilds a moment after the change of a value, because a `refresh()` that nobody awaits runs at the next turn of the event loop. A test polls for the new content and does not read it at once.
- `refresh()` returns an `AwaitableResponse`. An async handler that awaits it, for example `await view.refresh(editor)`, gets the new content before the await returns. A dialog that opens after such an await shows its form at once, also in the user simulation.
- In the user simulation, `await element.handle_uploads([SmallFileUpload(name, content_type, data)])` on a `ui.upload` calls its `on_upload` handler, with `SmallFileUpload` from `nicegui.elements.upload_files`. `trigger("rejected")` calls its `on_rejected` handler.
- A matrix of input elements goes into `ui.element("q-markup-table")` with `ui.element("thead")`, `"tbody"`, `"tr"`, `"th"` and `"td"` children. A real browser renders it as a table, and the user simulation finds each checkbox, select and switch of a cell by its marker. A Quasar table keeps each cell on one line. An inline `white-space: normal` lets a header cell wrap, and the Tailwind class `whitespace-normal` does not, because the rule of Quasar wins.
- A `ui.dialog` keeps `visible` true also when it is closed, so `user.find` finds the elements of a closed dialog. A test reads `dialog.value` to know whether the dialog is open.
- In the user simulation, `user.find` sees only visible elements, so an element that `bind_visibility_from` hides is not found. `ElementFilter(marker=..., local_scope=False)` inside `with user.client:` also finds the hidden ones.
- In the user simulation, `click()` does nothing on a disabled element, `type()` adds to the value, and `clear()` sets the value to `None`. `should_not_see` returns at the first check where the element is absent, so it does not wait for a handler that runs in the background. A test that proves that a click changed nothing waits a short time first.
- In the user simulation, `set_value` with the value that the element already has calls no `on_change`. A test that waits for a rebuild after such a call waits until its timeout.
- In the user simulation, a click on a `ui.select` opens its list, and a second `user.find("<option label>").click()` chooses the option. A `ui.radio` takes `value` of any hashable key, for example a `StrEnum` member, and `element.value` returns that member.
- `ui.table` rows and columns are props, not elements. `user.find` does not see the text of a cell, and a cell slot from `add_slot("body-cell-<name>", ...)` does not render in the simulation. A test reads `table.rows` and `table.columns`, so give each cell the ready display text.
- `table.on("rowClick", handler, js_handler="(event, row) => emit(row.id)")` sends only the id of the clicked row, and `e.args` in the handler is that id and not a list. In the simulation, `user.find(marker=...).trigger("rowClick", args=<id>)` calls the handler. A real browser run confirmed it.
- `ui.table(pagination=None)` hides the paging of Quasar and shows each row, and `pagination=50` gives `table.pagination == {"rowsPerPage": 50}`. For many rows, read one page from the database and use `ui.pagination(1, pages, value=page, on_change=...)`, where the handler reads `event.value`.
- A cell of a Quasar table stays on one line with an ellipsis only when the inner `div` has the class `ellipsis` and its own `max-width`. A `max-width` on the `q-td` does not truncate the text.
- `ui.input(...).props("type=date")` gives a text `YYYY-MM-DD`, and `clearable` gives `None` after the clear. A page that parses such a text moves the date into a range that `datetime` can convert to a time zone, because a date near year 1 or 9999 fails at the conversion.
- `ui.number` gives a `float` or `None`, also with `precision=0`. A page that needs whole numbers checks `float(value).is_integer()` and converts, because the `min` and `max` props check only in the browser.
- `ui.select(options, with_input=True)` searches by typing and works with the 598 names of `zoneinfo.available_timezones()`. The stored value must be one of the options, or NiceGUI raises a `ValueError`.
- ty reads the callback type of NiceGUI `Event.subscribe`, `Callable[P, Any] | Callable[[], Any]`, as `() -> Any` only, so it refuses a handler with arguments with `invalid-argument-type`. A subscribe of such a handler carries `# ty: ignore[invalid-argument-type]`.
- In the user simulation, a second `PatientUser(user.http_client)` is a second tab of the same service, with its own client.
- A page that reads the database with `asyncio.to_thread` after each change of a filter drops a read that ends after a newer read started. Without a counter of the reads, a slow old read replaces the newer table.
- A page follows the runs through one `RunFollower` (`web/ui/live_runs.py`), made in its builder before its first read. It holds back each event until `start()`, drops a `progress` after the `finished` of its run, and unsubscribes when it is deleted. NiceGUI starts the task of an async handler in the order of the emits, so a `progress` handler changes the page before its first await, and a handler that reads awaits `refreshable.refresh()`. A `refresh()` that nobody awaits runs at the next turn of the loop, with the targets of that later moment and the arguments of the call, so a refreshable that a progress also changes builds from the page state. The poll gives each action of a run only once, so History keeps the actions of the progress events that come while a read of the actions runs, and adds them to the result of the read.
- ty 0.0.91 refuses `RunEvents.started.subscribe(handler)` with a handler of the two parameters `run_id` and `trigger`, also with their types and as positional-only parameters: it reports the `Callable[[], Any]` side of the union of `Event.subscribe`. An untyped event, or a handler of `*args` with `expect_args=True`, passes.

- An icon-only button gets its name from `icon_button` in `web/ui/common.py`, which sets the tooltip and `props["aria-label"]`. Assign `props["aria-label"] = text` as a dict item: it needs no quoting, unlike `props('aria-label="..."')`. A Quasar button with `loading` hides its label, so a button that loads goes through `set_loading` (or `busy`), which gives it its text as `aria-label` for the time of the load. Do not set `loading` by hand.
- `element.tooltip(text)` of NiceGUI 3.18 makes a sibling `Tooltip` with the prop `target` (the id of the element), not a child. A test finds it by that prop. A `with button: ui.tooltip(...)` makes a child, which has no `target`.
- A table row that opens something on a click needs a keyboard path too: `add_row_button` and `actions_column` in `web/ui/common.py` add a column "Actions" with one `q-btn` for each row, and `@click.stop` keeps its click from the row. The event is `rowButton`, and `event.args` is the row id as for `rowClick`. The simulation does not render the slot, so a test reads `table.slots["body-cell-actions"].template` and triggers `rowButton`.
- Each server update that touches a `ui.table` makes Vue replace the cells of its rows, measured in Firefox: the button that had the keyboard focus is gone and the focus falls to `BODY`. A card or a table that a page rebuilds loses the focus the same way. So a page moves the focus by hand with `focus_when_drawn(selector, fallback=..., delay_ms=...)` in `web/ui/common.py`, which polls in the browser for about a second. It waits 200 ms (`FOCUS_DELAY_MS`) after a dialog closes. A card needs `tabindex=-1` to take the focus. The user simulation runs no JavaScript, so a test records the code with `monkeypatch.setattr(ui, "run_javascript", ...)`. Move the focus only after an action of the user, never after a refresh that a timer makes. Send the focus after the rebuild, not before: a save or a delete moves it after `await reload()`, because a read that takes longer than the delay would focus the old button. A handler that can run after its element is gone has no client in its context, so a page captures `context.client` once and passes it to `focus_when_drawn(client, ...)`. The browser gives up when the user moved the focus (`free()` in the script). `remember_focus(client)` before a slow read keeps the element that had the focus at that moment, so a key that the user presses during the read wins. A fallback selector is the second choice when the row is gone. A focus inside a dialog is free only for the dialog that held the start: a user who closes the editor and opens it again with Enter must keep the focus in the new dialog (measured in Firefox with 80 ms between the keys). The head script `accessibility_script()` also refocuses a row button by itself: it remembers the focused `[data-row-button]` on `focusin`, and when a redraw removes it and the focus is on BODY, it focuses the new button with the same row id in the same `data-row-scope`. A click on the page (`pointerdown`) forgets it. So a page that updates its table at each event of a timer or a run keeps the keyboard focus on the row button without code of its own. A card that a server event draws again keeps the focus the same way with `focus_key(element, key)`: the script remembers the control with `data-focus-key` that holds the focus, or an `input` inside it, and focuses the control with the same key after the redraw. The History run card, its Close and its Action filter have keys, measured in Firefox through the first action and the end of a run. NiceGUI builds a new Vue component for each slot template at each render of a table (`nicegui.js` 309-317), so each update of one row draws the button of each row again: a page sends a row only when its values change. A test patches `Client.run_javascript` with `recording_run_javascript` of `tests/conftest.py`.
- A row button has `data-row-button=<row id>`, and `add_row_button(..., scope=...)` puts `data-row-scope` on the table. A page with two tables of rows needs the scope. `event.sender` of a `table.on(...)` handler is the table.
- A control in a table cell, such as the switch Enabled of the rules table, is a slot template that calls `$parent.$emit(...)`. An emit with two values, for example `emit(id, value)`, gives `event.args` as a list, and an emit with one value gives the value itself (`client.py` 453-455). `@click.stop` on its `q-td` keeps the click from the row. The control gets its name from a field of the row (`:aria-label="props.row.<field>"`), so no user text runs in the template, and a `:data-focus-key` with the row id keeps its focus through the redraw. A column of `ui.table` takes a JavaScript sort as the key `":sort"`, which NiceGUI converts to a function, so the cell can show a text and sort by a number of the row.
- Quasar makes the header of a sortable column no stop of the Tab key and gives it no `aria-sort`. `add_keyboard_sort` in `web/ui/common.py` puts a `header-cell` slot with `tabindex`, Enter and Space that call `props.sort(props.col)`, `aria-sort` from the classes `sorted` and `sort-desc` of `props.col.__thClass`, and a focus key, because the sort draws the header again.
- NiceGUI draws the cells of a table again two or three times in the first 250 ms after a load, measured in Firefox on v1 too. A browser script that holds a cell element from the first draw gets a stale element, so it waits a moment after the load.
- `named(element, label)` sets `aria-label` on a select or a textarea that has no visible label. In Quasar the attribute lands on the `<label>` of the field, and Firefox gives the inner combobox that name (`accessible_name` of Selenium shows it). The select of the rows per page of a table and the buttons of `ui.upload` accept no prop, so `quasar_names_script()` in the head of each page sets their `aria-label` with a `MutationObserver`. `ui.upload` shows its add button only when it is enabled.
- A Vue template runs `{{ ... }}` in the text of a tooltip, so `row_button_template` writes each `{` of a label as `&#123;`.
- `ui.input(password_toggle_button=True)` makes an `<i aria-hidden>` with no role and no key. Use an `icon_button` in the `append` slot, with `aria-pressed`.
- A `click.prevent` listener with `js_handler="() => {}"` on `ui.skip_link` keeps `#c44` out of the address, and the click handler of the link still moves the focus.
- `ui.skip_link(text, target=element)` moves itself to the top of the layout and needs `target` to exist first, so the shell makes the content column before the link. The first Tab of a real browser reaches the link, and Enter gives the focus to the column.

## Translations

- Babel 2.18 reads the extraction mapping from `[tool.babel]` of `pyproject.toml` when you give `-F pyproject.toml`. It writes each location with `/`, also on Windows.
- The template `messages.pot` keeps each location without a line number and sorts the messages, so a moved line does not change it. The test compares the messages and ignores the header, because the header holds the creation date, the year and the version of Babel.
- Babel 2.18 copies a `# Translators:` comment into the template only when the call of `_` is on the line right after the comment. A comment above `ui.page_title(_("..."))`, `ui.label(_("...").format(...))` or `title = _("...")` goes into the template. A comment above `ui.label(` with `_(` one line lower does not, and ruff format makes such a split of a long line. A comment of two lines above `text = _("...").format(...)` also goes into the template.
- `pybabel extract` ends the template with an empty line, and the hook `end-of-file-fixer` removes it. The test ignores this difference.
- The language is one setting `ui_language` of the service (`i18n/setting.py`). `_` reads the module global `i18n._translations` at each call, and `set_language` replaces it. The lifespan calls `set_language` only when the stored language differs from the current one: the page tests that patch `i18n._translations` with a marking object before the service starts keep their patch. The autouse fixture `english_texts` of `tests/conftest.py` puts English back after each test, and the fixture `uk_catalog` compiles `tests/fixtures/i18n/uk.po` into a folder of the test.
- NiceGUI reads `app.config.language` when it renders a page, after the page function (`Client.build_response`, `page.resolve_language`), and the page loads `static/lang/<language>.umd.prod.js` of Quasar. So the shell sets it from `i18n.language()` at each full load, and the language button loads the page again with `RELOAD_SCRIPT` of `web/ui/layout.py`. Measured in Firefox: after the reload the month names of `Quasar.lang` and the "No data available" text of a table are Ukrainian, and `<html lang>` is `uk`. With `None`, NiceGUI omits `lang`, so English is `en-US`.
- The date fields of the pages are native `type=date` inputs, not the Quasar `ui.date`, so the Quasar language pack does not change their texts.
- After the user chose to stay on the page in the warning of the browser before a reload, Firefox refuses each later reload of that page by a script: `location.reload()` and `history.go(0)` of `ui.navigate.reload` do nothing, also 20 s later. `location.replace` and `location.assign` of an address still load it, but not an address that differs only in its fragment, which only scrolls. So `RELOAD_SCRIPT` is `location.replace(location.pathname + location.search)`, and a page that opens a part by its fragment writes the fragment again when it builds.
- The Ukrainian catalog `i18n/locale/uk/LC_MESSAGES/messages.po` is in git, and the `.mo` file is not (`*.mo` in `.gitignore` and `.dockerignore`). `just po` runs `pybabel update --init-missing --ignore-obsolete`, `just mo` runs `pybabel compile`, and the `catalog` stage of the Dockerfile compiles the `.mo` with the dev group only (`uv sync --only-group dev`), so the runtime image copies the `.mo` and no dev package. `tests/test_i18n_catalog.py` reads the `.po` and needs no `.mo`: it fails on a missing, untranslated, fuzzy, obsolete or extra message and on a different set of `{placeholders}`.
- `pybabel update` writes the header of the `.po` back with the placeholders of the template (`Report-Msgid-Bugs-To: EMAIL@ADDRESS`, `Last-Translator: FULL NAME <EMAIL@ADDRESS>`, two spaces after `Project-Id-Version:`), also after you delete them by hand. The committed header has that stable form, so `just po` on a clean tree changes nothing. A new message that looks like a changed old one comes back fuzzy, and the test fails until a person checks it and removes the flag.
- The REST API answers in English whatever the language of the pages is. The only text that reaches it through `_()` is the error of `validate_name` and `validate_playlist` of `rules_store.py` (the 422 `detail` of `POST` and `PUT /api/rules`). These functions and `validate_draft` take `say`, a function from the English message to its text. The default is `_` (the pages), and the API passes `AS_ENGLISH` (`N_`). The messages are constants marked with `N_`, so the extraction keeps them. A new `_()` outside `web/ui` must not reach an API answer without `AS_ENGLISH`.
- The template has no plural form, so the Ukrainian text cannot agree a noun with a number. It uses a colon («Додано відео: {count}»), an indeclinable word («відео») or an abbreviation («дн.», «хв», «с») next to each `{count}`, `{days}` and `{minutes}`.
- Glossary of the Ukrainian catalog, one word for one thing: rule — правило, playlist — плейлист, subscription — підписка, channel — канал, source (a channel or the subscriptions feed) — джерело, run — запуск, scheduler — Планувальник, schedule — розклад, apply — застосування, preview — попередній перегляд, condition — умова, retention — зберігання, session — сесія, cookies — cookies (not declined), cookie rotation — автооновлення, target of a notification — адресат, account — акаунт, service — сервіс, Dashboard — Огляд, History — Історія, Settings — Налаштування, "seen" video — побачене відео, "Also add videos from" — «Додати також відео від» (the texts name the field by this label), yt-dlp release channel — тип випуску (the names Stable and Nightly stay English).
- The language button names the language of its click, in that language («Українська» on an English page, «English» on a Ukrainian page), outside the template. The tests that check that each text of a page goes through the translation accept `NAMES.values()`.

## Apprise

- Apprise sends one message to many services. A tag on a target routes a message to a subset of the targets. A message has one of four types: info, success, warning and failure.
- Apprise 2.0.1 has no `msteams://` schema. A message to Microsoft Teams goes through the Power Automate schema `workflow://`.
- Apprise 2.0.1 limits each HTTP request of a target to 4 s to connect and 4 s between two reads (`URLBase.socket_connect_timeout` and `socket_read_timeout`). A URL changes them with the arguments `cto` and `rto`. The email plugin connects with 15 s. A target can send several requests, for example one for each chat, with a pause of 5.5 s between them (`NotifyBase.request_rate_per_sec`), so Apprise does not limit the time of a whole target. `notify._deliver` therefore sends in a daemon thread and gives up after `DELIVER_TIMEOUT_S` (30 s).
- The scheduler page sends `scheduler_state` after Pause, Resume, and a save that turns the switch, through `asyncio.to_thread`.
- Youtarr is an example of a notification design on Apprise. It sends one summary for each run, not one message for each item. It sends to each target separately, so one failed target does not stop the others. It removes the target URLs from its logs, because a target URL holds a token.
